And the deployed ELSA 3 scene record carries `product_id: null` with `acquired_utc` set to the search window's end rather than the acquisition instant, because the `.meta.json` sidecars beside the cached GeoTIFF were not copied into the server's data volume — `data/` is in `.dockerignore` and the volume was populated by hand. Both instants are above the 10 m/s ceiling and the scene gates either way, so the verdict is unaffected, but the number on screen is not the number at the acquisition.

## What would clear the remaining rows

**AC-12 is a two-token path fix.** Correct `SYNTHETIC_SET` in `tests/integration/test_attribution.py` to `parents[2] / "fixtures" / "scenarios" / "synthetic_set.json"`. The set it needs is already on disk with 50 cases and 16 negative controls, and it already satisfies the assertion the test would make; the only thing missing is the test reading it. This is the single cheapest remaining item in the table and it turns the project's headline accuracy figure from an asserted number into a verified one.

**AC-26 is six findings and a decision.** `ruff check --fix tests` clears the two unused imports. The four mypy errors are two `requests` `params` annotations, one generator item type and one shadowed local. What needs a decision rather than typing is whether `--ignore-missing-imports` is adopted as the project's standard or `--strict` is committed to, because at `--strict` the count is ninety.

**The GFW gap timeout should degrade like the infrastructure refusal does.** `gaps_by_mmsi` currently converts an unavailable source into an empty result, which silently weakens the `ais_gap_overlap` prior. Returning a status alongside the events, as `infrastructure()` already does, would make the integration test's failure message tell the truth and would stop a network timeout from reading as evidence of no gaps. This is the last remaining red stage in `verify.sh`.

**AC-13 is the one that needs thought rather than typing.** Asserting that the credible interval widens monotonically with slick age means running one case at several acquisition lags and comparing interval widths — a slow integration test. It is also the assertion behind a claim the PPT already made, so it should not simply be dropped.

**AC-16 needs a replay harness**, not more hashing: load a manifest, re-fetch every input by its recorded hash, re-run and compare posteriors within tolerance.

**AC-22 needs a `toHaveScreenshot` baseline** if visual stability is to be claimed at all; the horizontal-scroll half of the criterion is already properly covered. **AC-24 needs the badge assertion widened** from the scenario deck to the per-panel data surfaces.

**AC-1 and AC-27 both need the same thing**: the tree under version control, a clean clone, and one recorded `docker compose up` against it.

## Smaller defects found while compiling this record

These are below the level of an acceptance criterion but they are real, they are reproducible, and they should not be discovered by a reviewer first.

The **wind-gate speed disagrees with itself on the deployed ELSA 3 card.** `core/sar/windgate.evaluate` now rounds once and builds both the stored figure and the verdict sentence from that single value, with a comment saying so. The record currently in the deployed database was written by an image that predates the consolidation: it stores `wind_speed_ms: 11.15`, with a verdict sentence already reduced to *11.1 m/s*. The console formats the stored figure with `toFixed(1)`, which renders it as **11.2**. So the large *Speed* statistic reads 11.2 and the sentence directly beneath it reads 11.1. The fix is already in the tree and the discrepancy disappears when the scene is re-ingested; until then it is on screen.

The **cached-scene path loses its metadata when the sidecar is absent.** `CdseClient` reads `product_id` and `acquired_utc` from the `.meta.json` beside a cached GeoTIFF and falls back to `None` for both when the file is missing. `core/pipeline` then falls back from a null `acquired_utc` to the end of the search window, and evaluates the wind gate at that instant. On the deployment, where only the `.tif` was copied into the data volume, this is why the ELSA 3 record shows a null product id and a wind speed measured a day after the acquisition. A missing sidecar should refuse or warn, not silently substitute a different time.

The **Calibration page labels 133 pairs as "Held-out cases".** The held-out split is 67 pairs and is what the isotonic metrics are computed on; 133 is the full set the reported Brier and ECE are computed on. The number is right and the label is wrong. The same page's footer line reads *isotonic regression fitted on a held-out split* without adding *and not applied*, which the note directly above it does say.
